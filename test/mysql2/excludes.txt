# --- client-side prepared statements interpolate a bound Time/DateTime as a quoted string
#     literal, so `SELECT ? AS a` returns a VAR_STRING column (not a typed DATETIME the binary
#     protocol would echo back). Not exercised by ActiveRecord, which reads real typed columns. ---

# --- probe internal Ruby ivars (result's @query_options, client's @current_query_options)

# --- #escape is pure string processing (no server round-trip), so it doesn't check the
#     connection state the way libmysqlclient's mysql_real_escape_string does ---
#escape should require an open connection

# --- interrupting an in-flight query: JRuby can't preempt a blocking JDBC socket read, so a Ruby
#     Timeout/Thread#raise only fires after the query completes -- the connection stays healthy
#     rather than being torn down mid-read the way libmysqlclient's unblock function does. (Use
#     :read_timeout, which maps to JDBC socketTimeout, to bound a query.) Also, Connector/J reports
#     a killed connection as "Communications link failure" (08S01), not libmysql's "Lost connection",
#     and the socket-state follow-ups need #socket, which JDBC doesn't expose. ---
should detect closed connection on query read error
should close the connection when an exception is raised
should handle Timeouts without leaving the connection hanging if reconnect is set to true after construction

# --- streaming (stream: true) — not implemented: results are always buffered client-side and
#     re-iterable, so single-pass semantics (advancing #first, iterate-twice / query-again locks,
#     mid-stream timeouts) don't apply ---
should yield different value for #first if streaming
should throw an exception if we try to iterate twice when streaming is enabled
should raise an exception if streaming ended due to a timeout
should not let you query again if iterating is not finished when streaming
